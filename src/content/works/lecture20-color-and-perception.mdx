## 这节课在 GAMES101 里到底讲什么？

第 20 课 **Color and Perception** 的核心不是“RGB 怎么调色”，而是建立一条完整链路：

```text
真实世界的光谱
-> 人眼视锥细胞响应
-> 大脑形成颜色感知
-> CIE 等标准颜色空间
-> 渲染器里的线性 RGB
-> 显示器上的 sRGB / HDR 输出
-> 最终被人眼再次感知
```

这一课最重要的一句话是：

> 颜色不是光的固有属性。物理世界里只有不同波长的电磁辐射；颜色是人眼和大脑对这些刺激的感知结果。

这句话会直接解释很多图形学里常见的问题：

- 为什么真实光不是 RGB？
- 为什么不同光谱可以看起来是同一种颜色？
- 为什么渲染必须在线性空间做光照？
- 为什么贴图有的要 sRGB 解码，有的不能解码？
- 为什么 HDR 图像必须 tone mapping 才能显示？
- 为什么物理正确的 radiance 不一定看起来舒服？

## 0. 先把“颜色”拆成四层

颜色这个词很容易混乱，因为它同时跨越物理、生理、心理和工程。

| 层次 | 研究对象 | 图形学里的对应问题 |
|---|---|---|
| 物理 Physics | 光的波长和能量分布 | 光源 SPD、材质光谱反射率、spectral rendering |
| 生理 Physiology | 视锥和视杆如何响应 | LMS、亮度敏感度、色盲、暗视觉 |
| 心理 Perception | 大脑如何解释颜色 | 同时对比、色恒常、适应、错觉 |
| 工程 Engineering | 如何编码、传输和显示颜色 | RGB、XYZ、sRGB、P3、gamma、tone mapping |

很多 bug 都来自把这几层混在一起。例如：

```text
把 RGB 当成真实光谱      -> 解释不了同色异谱和复杂光源
把 sRGB 当成线性能量     -> 光照变脏、变暗或过亮
把显示颜色当成感知颜色   -> 忽略环境、适应和对比
把 tone mapping 当成可选 -> HDR 高光直接 clipping
```

## 1. 光谱：真实光不是 RGB

真实可见光是一段波长范围内的电磁波，大约从 380nm 到 700nm。不同波长刺激人眼后，会产生紫、蓝、绿、黄、红等颜色感知。

描述一束光最物理的方式是 **Spectral Power Distribution / SPD**，也就是每个波长上有多少能量。

```text
SPD(lambda) = power at wavelength lambda
```

不同光源的 SPD 很不一样：

| 光源 | 光谱特点 | 视觉印象 |
|---|---|---|
| 太阳光 | 比较连续，覆盖宽 | 自然、中性 |
| 蓝天 | 短波散射更强 | 偏蓝 |
| 白炽灯 | 长波能量更多 | 暖黄、偏橙 |
| 荧光灯 | 多个尖峰 | 可能显色不自然 |
| 白 LED | 蓝峰 + 荧光粉宽峰 | 常见但光谱不连续 |
| 激光 | 极窄波段 | 颜色纯、饱和 |

<SpectralPrismEye3D client:only='react' />

RGB 不是自然界的基本物理量。它只是工程上用三个数字近似人眼颜色感知的一种编码。

### 物体颜色也不是固定 RGB

一个物体表面的“颜色”来自两件事相乘：

```text
入射光谱 × 材质的光谱反射率 = 进入眼睛的光谱
```

所以同一件衣服在日光、白炽灯、LED 商店灯下可能看起来不同。这不是衣服突然改变了，而是光源 SPD 变了，乘出来进入眼睛的光谱也变了。

## 2. 光谱渲染 vs RGB 渲染

如果最真实的量是光谱，为什么大多数渲染器仍然用 RGB？因为光谱渲染更贵。

| 渲染方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| RGB rendering | 每条光线携带 R/G/B 三个通道 | 快、和显示器匹配、工程简单 | 不能完整模拟波长相关现象 |
| Spectral rendering | 采样多个波长或光谱基函数 | 更物理，能处理色散、复杂光源和同色异谱 | 计算和材质数据更复杂 |

RGB 渲染能应付绝大多数游戏和实时图形，但下面这些现象更适合光谱渲染：

- 棱镜把白光分解成彩虹。
- 钻石和玻璃的色散。
- 荧光材料吸收一种波长、发出另一种波长。
- 某些布料或颜料在不同光源下颜色匹配失效。
- 高精度产品可视化和电影级离线渲染。

GAMES101 这里的重点是：先理解真实光是光谱，再理解 RGB 只是人眼和显示器之间的工程压缩。

## 3. 人眼不是光谱仪：LMS 三类视锥细胞

人眼白天主要依赖三类 cone cells / 视锥细胞：

| 视锥 | 大致敏感区域 | 容易误解的名字 |
|---|---|---|
| S cone | 短波，对蓝紫区域更敏感 | 不是“只看蓝光” |
| M cone | 中波，对绿色区域更敏感 | 不是“只看绿光” |
| L cone | 长波，对黄红区域更敏感 | 不是“只看红光” |

关键是：三类视锥的响应曲线都很宽，而且互相重叠。人眼不会完整记录每个波长的能量，只会把光谱压缩成大约三个响应值：

```text
incoming spectrum -> L response, M response, S response
```

这就是三刺激理论成立的生理基础。

### 为什么不是“RGB 视锥”？

LMS 和显示器 RGB 不是同一件事：

| LMS | RGB |
|---|---|
| 人眼生理响应 | 工程显示和存储通道 |
| 响应曲线宽且重叠 | 由显示器三种 primaries 决定 |
| 不能直接当像素值 | 可以编码到图片和 framebuffer |

显示器的 RGB 设计目标，不是复现真实世界光谱，而是用三种发光 primaries 激发人眼产生目标 LMS 响应。

## 4. 视杆细胞、亮度和暗视觉

除了 cones，人眼还有 rods / 视杆细胞。它们在低光环境下更重要。

| 细胞 | 工作环境 | 主要感知 |
|---|---|---|
| Cones | 明亮环境 | 颜色和细节 |
| Rods | 暗光环境 | 亮度、运动、弱光 |

这解释了几个生活现象：

- 夜晚颜色变得不明显，因为 cones 工作弱，rods 主导。
- 人眼对绿色附近的亮度更敏感。
- 暗处看星星时，稍微用余光看可能更容易看到，因为视杆在视网膜外围更多。

在渲染中，虽然我们通常不模拟完整人眼生理，但 tone mapping 和曝光控制会借鉴人眼对亮度的非线性感知。

## 5. 同色异谱 Metamerism：不同光谱，看起来一样

**Metamerism / 同色异谱** 是颜色科学中最关键的概念之一：

> 两个完全不同的光谱，只要对三类视锥产生相同或足够接近的 LMS 响应，人眼就可能觉得它们是同一种颜色。

最常见的例子：

| 看起来 | 实际光谱 |
|---|---|
| 日光下的白色 | 连续宽光谱 |
| 显示器上的白色 | 红、绿、蓝三个 primaries 混合 |

它们 SPD 完全不同，但都能让人眼感到“白”。

### 同色异谱为什么重要？

它解释了：

1. RGB 显示器为什么可行：只要匹配人眼响应，不需要重建完整光谱。
2. 照片为什么能表示颜色：相机 RGB 传感器试图近似人眼响应。
3. 商品为什么会“灯下同色、日光下不同色”：两个材质在一种光源下 LMS 匹配，换光源后不匹配。
4. 光谱渲染为什么仍有价值：RGB 丢掉了同色异谱背后的真实光谱差异。

## 6. Color Matching Experiment：颜色空间从实验来

为了标准化颜色，人们做了 color matching experiment。

实验直觉：

```text
给观察者一个测试颜色
让观察者调节三种基色的强度
直到混合光看起来和测试颜色一样
记录三种基色需要的强度
```

这个实验告诉我们：在正常三色视觉下，大量颜色感知可以用三个数表示。

但早期 RGB matching functions 会出现负值。负值的意思不是负光，而是某些颜色无法用给定三基色直接混合出来，需要把某个基色加到测试光那一边才能匹配。

为了得到更方便的标准，CIE 定义了 XYZ 色彩空间。

## 7. CIE XYZ：设备无关的三刺激空间

CIE 1931 XYZ 是一个标准观察者下的设备无关颜色空间。

| 分量 | 作用 |
|---|---|
| X | 三刺激值之一，数学构造出来方便覆盖可见颜色 |
| Y | 特意设计得接近人眼亮度响应 |
| Z | 三刺激值之一，和短波响应相关较强 |

XYZ 的重要性在于：它可以作为不同设备和颜色空间之间转换的中间语言。

```text
camera RGB -> XYZ -> display RGB
renderer RGB -> XYZ -> output color space
spectral data -> XYZ -> RGB preview
```

### 色度坐标 xy

为了只讨论“色相和饱和度”，可以把亮度规模除掉，得到 chromaticity：

```text
x = X / (X + Y + Z)
y = Y / (X + Y + Z)
z = Z / (X + Y + Z)
```

因为 `x + y + z = 1`，通常只画 x 和 y，这就是 CIE chromaticity diagram。

### 色度图的直觉

- 马蹄形边界表示单波长光谱色。
- 中间靠近白点的位置饱和度低。
- 两个颜色混合会落在线段之间。
- 三个显示 primaries 能覆盖的颜色是一个三角形。

这直接引出下一个概念：色域。

## 8. Gamut 色域：设备能显示哪些颜色

色域是某个颜色空间或设备能表示的颜色范围。

| 色彩空间 | 常见用途 | 特点 |
|---|---|---|
| sRGB | Web、普通图片、默认显示 | 最常见，色域相对小 |
| Rec.709 | HDTV | 和 sRGB primaries 接近 |
| Display P3 | 手机、Mac、现代显示器 | 红绿范围比 sRGB 更宽 |
| Adobe RGB | 摄影、印刷 | 绿色覆盖更广 |
| Rec.2020 | UHD / HDR 标准 | 色域很大，显示设备难完全覆盖 |
| ACEScg | 影视渲染工作空间 | 宽色域，适合中间计算 |

<GamutToneMappingLab client:only='react' />

<GamutVolume3D client:only='react' />

最重要的工程结论：

> 同一个 RGB 数字，在不同色彩空间中不是同一个颜色。

例如：

```text
RGB = (1, 0, 0)
```

在 sRGB 里表示 sRGB 的红 primary；在 Rec.2020 里表示 Rec.2020 的红 primary。二者在 CIE 图上的位置不同，所以不是同一个物理颜色。

### 超出色域怎么办？

如果渲染结果包含目标显示器无法显示的颜色，就需要 gamut mapping。

常见处理：

| 方法 | 结果 |
|---|---|
| Clip | 直接截断，可能丢细节和变色 |
| Compress | 把颜色压回色域，保留层次 |
| Perceptual mapping | 尽量保持观感关系 |
| Artistic grading | 按美术意图调整 |

## 9. RGB、线性 RGB 和 sRGB：最容易出 bug 的地方

RGB 只是三个通道，但它们可以处在不同编码状态。

| 名字 | 含义 | 能不能直接做光照计算？ |
|---|---|---|
| Linear RGB | 数值与光能量成正比 | 可以 |
| sRGB | 为显示和存储设计的非线性编码 | 不可以直接算光照 |
| Display RGB | 送到设备的编码值 | 取决于输出标准 |

光照是能量运算，能量相加必须在线性空间做。

错误流程：

```text
baseColor_srgb = readTexture()
lighting = baseColor_srgb * NdotL
output = lighting
```

正确流程：

```text
baseColor_linear = srgbToLinear(readTexture())
lighting_linear = evaluateBRDFAndLighting(baseColor_linear)
hdr_color = accumulateGIAndEmission(lighting_linear)
tone_mapped = toneMap(hdr_color)
output_srgb = linearToSrgb(tone_mapped)
```

### 哪些贴图应该 sRGB 解码？

| 贴图 | 是否 sRGB 解码 | 原因 |
|---|---|---|
| Base Color / Albedo | 是 | 表示颜色 |
| Diffuse Color | 是 | 表示颜色 |
| Emissive Color | 通常是 | 表示颜色，但强度可能另有 HDR 倍率 |
| Normal Map | 否 | 表示方向数据 |
| Roughness | 否 | 标量材质参数 |
| Metallic | 否 | 标量材质参数 |
| Ambient Occlusion | 否 | 遮蔽系数 |
| Height / Displacement | 否 | 几何或高度数据 |
| Opacity / Alpha mask | 通常否 | 覆盖率或 mask 数据 |

把 normal map 当 sRGB 读，会把方向数据非线性扭曲；把 roughness 当 sRGB 读，会让粗糙度分布完全变味。

## 10. Gamma、OETF、EOTF：为什么 0.5 不简单？

人眼对暗部变化更敏感，对亮部变化相对不那么敏感。为了更有效利用 8-bit 存储，sRGB 使用了非线性编码，让暗部获得更多编码精度。

粗略说：

```text
0.5 in sRGB is not 0.5 physical light energy
```

更准确的几个术语：

| 术语 | 含义 |
|---|---|
| Scene-linear | 渲染器内部的线性物理或近似物理值 |
| OETF | 把线性场景值编码成非线性信号 |
| EOTF | 显示器把信号转换成显示亮度 |
| Gamma correction | 常用来泛指线性和非线性编码之间的转换 |

在现代管线里，尤其 HDR 中，术语会更严格，例如 PQ、HLG、display-referred、scene-referred 等。但 GAMES101 阶段最重要的是：

> 光照计算在线性空间；显示和普通图片存储通常不是线性空间。

## 11. 白点、色温与白平衡

白色不是绝对的。不同光源的“白”有不同光谱。

| 光源 | 大致色温 | 观感 |
|---|---:|---|
| 烛光 | 约 1800K | 很暖、橙红 |
| 白炽灯 | 约 2700K | 暖黄 |
| 正午日光 / D65 | 约 6500K | 标准日光白点 |
| 阴天蓝天 | 8000K 以上 | 偏冷、偏蓝 |

人眼具有 chromatic adaptation / 色适应：在暖光下看白纸，过一会儿大脑仍然会把它解释为白纸。

相机的 white balance 就是在选择：

```text
哪一种光源应该被当作白色参考？
```

如果白平衡错了：

- 室内白炽灯照片可能整体偏黄。
- 阴天照片可能偏蓝。
- 混合光源下某些区域正常，另一些区域偏色。

渲染中也有类似问题：HDRI 环境、灯光色温、材质 albedo 和输出 transform 共同决定最终白点观感。

## 12. HDR：渲染器内部的亮度远超屏幕

真实世界动态范围非常大：

| 场景 | 亮度关系直觉 |
|---|---|
| 室内白墙 | 中等亮度 |
| 灯泡表面 | 比墙亮很多 |
| 太阳反射高光 | 极亮 |
| 夜晚阴影 | 很暗 |
| 室外阳光与室内暗部 | 可相差数千到数万倍 |

渲染器内部常常使用 scene-linear HDR 值，例如：

```text
0.18  middle gray
1.0   reference white-ish
10.0  bright highlight
100.0 extremely bright light source
```

但普通 SDR 显示器只能显示有限范围，例如 0 到 1 的输出编码。直接 clamp 会发生：

```text
value 2, 10, 100 all become 1
```

高光层次全部丢失。所以需要 tone mapping。

## 13. Tone Mapping：把 HDR 压到显示范围

Tone mapping 的任务不是简单缩放，而是把高动态范围场景值转成显示范围，同时尽量保持视觉层次。

典型显示管线：

```text
scene-linear HDR
-> exposure
-> tone mapping curve
-> color grading
-> gamut mapping
-> output transform
-> display
```

常见 tone mapping 曲线：

| 方法 | 特点 |
|---|---|
| Linear + clamp | 简单但高光死白 |
| Reinhard | 公式简单，高光柔和压缩 |
| Filmic | 模拟胶片肩部和 toe，观感自然 |
| ACES-like | 现代实时渲染常用，影视管线友好 |
| Custom curve | 按项目美术风格控制 |

Tone mapping 需要同时考虑：

- 中间调不能灰掉。
- 高光要有 roll-off，不要硬截断。
- 暗部要有层次但不能泛灰。
- 饱和高光不能严重偏色。
- 输出设备可能是 SDR、HDR、P3 或 Rec.2020。

### Exposure 曝光

在 tone mapping 前通常先做 exposure：

```text
exposedColor = sceneColor * exposureMultiplier
```

摄影里可以用 EV 理解曝光变化：增加 1 stop，亮度约乘 2；减少 1 stop，亮度约除 2。

## 14. Perception：人眼不是线性测光仪

即使物理 radiance 完全正确，人眼感知也不只是线性读数。

| 感知现象 | 说明 | 对渲染的启发 |
|---|---|---|
| Simultaneous Contrast | 同一灰色在不同背景上看起来不同 | 调色要考虑周围环境 |
| Mach Bands | 明暗边界附近会感到额外边缘 | 过度锐化或渐变可能出假边 |
| Color Constancy | 光源变了，物体颜色仍被感知相对稳定 | 白平衡和色适应很重要 |
| Adaptation | 从亮处到暗处需要时间适应 | 自动曝光、eye adaptation |
| Helmholtz-Kohlrausch | 高饱和颜色可能被感到更亮 | 饱和度会影响亮度观感 |
| Hunt Effect | 亮度越高，颜色看起来越鲜艳 | HDR 显示需要感知映射 |

这就是为什么电影和游戏最终需要 color grading。物理正确是基础，但最终目标通常是“感知上合理、叙事上好看”。

## 15. Alpha、预乘和线性合成

颜色管线里还有一个常见坑：透明合成。

非预乘 alpha：

```text
rgb = color
alpha = coverage
```

预乘 alpha：

```text
rgb = color * alpha
alpha = coverage
```

预乘 alpha 的 over 合成公式可以写成：

```text
out.rgb = fg.rgb + bg.rgb * (1 - fg.alpha)
out.a   = fg.a   + bg.a   * (1 - fg.alpha)
```

关键点：

> 透明合成也应该在线性空间做。

如果在 sRGB 空间合成，半透明边缘会出现错误暗边或亮边，UI、粒子、树叶 alpha、头发边缘都可能出问题。

---

## 16. 一条实用颜色管线清单

写引擎或 shader 时，可以按这个顺序检查颜色是否正确：

```text
1. 输入贴图
   - baseColor / emissive: sRGB -> linear
   - normal / roughness / metallic / AO: no sRGB decode

2. 材质和光照
   - BRDF, shadows, GI, bloom threshold all in scene-linear
   - HDR values allowed, do not clamp early

3. 后处理
   - exposure in linear HDR
   - bloom from HDR bright regions
   - tone mapping compresses HDR to display range

4. 输出
   - gamut mapping to target color space
   - linear -> sRGB or HDR output transform
   - UI and alpha compositing need consistent color space
```

最常见的排错方法：

| 症状 | 优先检查 |
|---|---|
| 画面整体发灰 | 是否重复 gamma、tone mapping 曲线是否不对 |
| 画面太暗 | 是否把 sRGB 当 linear 做光照 |
| normal map 怪异 | normal 是否被 sRGB 解码 |
| roughness 不对 | roughness map 是否被 gamma 处理 |
| 高光一片死白 | 是否直接 clamp，缺 tone mapping |
| 透明边缘黑边 | 是否在非线性空间合成或预乘处理错误 |
| P3 图片颜色怪 | 是否忽略色彩空间标签 |

## 17. 从 GAMES101 到实际项目：你应该记住什么？

| 概念 | 一句话抓重点 | 项目中怎么用 |
|---|---|---|
| Spectrum | 真实光是按波长分布 | 理解光源、色散和复杂材质 |
| LMS | 人眼把光谱压成三类响应 | 理解 RGB 为什么可行 |
| Metamerism | 不同光谱可同色 | 理解显示器和材质换灯变色 |
| CIE XYZ | 标准设备无关颜色空间 | 做颜色空间转换的中间参考 |
| Gamut | 设备能显示的颜色范围 | sRGB、P3、Rec.2020 不能混用 |
| Linear RGB | 能量计算空间 | 所有光照和合成尽量在线性做 |
| sRGB / Gamma | 存储和显示编码 | 贴图读取和最终输出要转换 |
| White Balance | 选择参考白 | 控制整体冷暖和光源适应 |
| HDR | 渲染内部高动态范围 | 不要过早 clamp |
| Tone Mapping | HDR 到显示范围 | 决定高光、中间调和整体观感 |
| Perception | 人眼受上下文影响 | 需要曝光、调色和感知映射 |

## 总结

第 20 课的重点是：**颜色是一条从物理光谱到人眼感知，再到工程显示的完整链路。**

真实世界给我们的是光谱，人眼把它压缩成感知，颜色科学用 XYZ 和色域把它标准化，渲染器用线性 RGB 近似计算光照，显示前再经过曝光、tone mapping、gamut mapping 和输出变换。理解这条链路后，很多“颜色为什么不对”的问题都会变得可定位、可解释、可修。
