## 01 / Shadow Mapping 快速回顾

> 核心问题：为什么要回顾？因为 GAMES202 的所有进阶技术都是在修补 Shadow Mapping 的固有缺陷。

### Two-Pass 流程

**Pass 1 - 光源视角深度渲染：**
```glsl
// Vertex Shader (Light Pass)
gl_Position = lightProjection * lightView * model * vec4(position, 1.0);

// Fragment Shader (Light Pass)
// 只写深度，颜色不重要
```

**Pass 2 - 相机视角着色 + 阴影测试：**
```glsl
// 把片元位置变换到光源空间
vec4 fragPosLightSpace = lightProjection * lightView * vec4(worldPos, 1.0);
vec3 projCoords = fragPosLightSpace.xyz / fragPosLightSpace.w;
projCoords = projCoords * 0.5 + 0.5; // NDC -> [0,1]

float closestDepth = texture(shadowMap, projCoords.xy).r;
float currentDepth = projCoords.z;
float shadow = currentDepth - bias > closestDepth ? 1.0 : 0.0;
```

### Shadow Mapping 的三大固有问题

| 问题 | 根源 | 视觉表现 |
|------|------|----------|
| **Self-shadowing / Acne** | 深度离散化 + 浮点精度 | 表面出现斑驳条纹 |
| **Aliasing / 锯齿** | Shadow map 分辨率有限 | 阴影边缘像素化 |
| **Hard Shadow** | 点光源假设 | 没有半影，边界生硬 |

<ShadowAcneBiasLab client:only="react" />

**关键认知：**
- Bias 解决 acne，但引入 peter panning（阴影漂浮）
- 提高分辨率缓解锯齿，但成本平方增长
- 硬阴影不符合物理，真实光源都有面积

> GAMES202 的核心就是：**如何在实时预算内解决这三个问题**

## 02 / PCF 的数学本质

> 核心问题：PCF 到底在过滤什么？为什么不能直接模糊深度图？

### PCF ≠ Blur Shadow Map

很多初学者认为 PCF 就是"把 shadow map 模糊一下"。**这是错的**。

正确理解：
```text
❌ 错误：blur(depth) → compare
✓ 正确：compare → average(results)
```

**为什么不能先模糊深度？**

假设一个场景：
- Shadow map 某处记录深度 0.5
- 周围 texel 深度分别是 0.3, 0.7
- 模糊后得到平均 (0.3 + 0.5 + 0.7) / 3 = 0.5
- 当前片元深度 0.6

如果先模糊：0.6 > 0.5 → shadow
如果用 PCF：
- 0.6 > 0.3 → shadow (1.0)
- 0.6 > 0.5 → shadow (1.0)  
- 0.6 < 0.7 → lit (0.0)
- 平均 = (1 + 1 + 0) / 3 = 0.67 → 半影

**深度不能线性插值用于可见性判断！**

### PCF 的正确实现

```glsl
float PCF(sampler2D shadowMap, vec2 uv, float currentDepth, float bias) {
    float shadow = 0.0;
    vec2 texelSize = 1.0 / textureSize(shadowMap, 0);
    
    // 3×3 kernel
    for(int x = -1; x <= 1; ++x) {
        for(int y = -1; y <= 1; ++y) {
            vec2 offset = vec2(x, y) * texelSize;
            float pcfDepth = texture(shadowMap, uv + offset).r;
            shadow += currentDepth - bias > pcfDepth ? 1.0 : 0.0;
        }
    }
    shadow /= 9.0;
    return shadow;
}
```

<PCFFilteringDemo client:only="react" />

### PCF 的性能特征

| Kernel 大小 | 采样次数 | 适用场景 |
|------------|----------|----------|
| 3×3 | 9 | 移动端、快速近似 |
| 5×5 | 25 | PC 默认配置 |
| 7×7 | 49 | 高质量设置 |
| Poisson Disk | 16-32 | 降低采样数但保持质量 |

**关键优化：**
- 使用 Poisson Disk 采样替代规则网格
- Early-out：如果中心点远离阴影边界，跳过采样
- Mipmap：远处用小 kernel

## 03 / PCSS：统计学逼近物理软阴影

> 核心问题：真实软阴影的半影宽度应该随遮挡物距离变化，PCF 做不到这一点。

### 物理软阴影的形成

面积光源 → 某些方向被遮挡，某些方向可见 → 半影

**半影宽度估算：**

$$
w_{\text{penumbra}} = \frac{d_{\text{receiver}} - d_{\text{blocker}}}{d_{\text{blocker}}} \times w_{\text{light}}
$$

其中：
- $d_{\text{receiver}}$：接收点到光源的距离
- $d_{\text{blocker}}$：遮挡物到光源的平均距离  
- $w_{\text{light}}$：光源尺寸

**直觉：**
- 遮挡物离接收面越近 → 半影越窄（锐利）
- 遮挡物离接收面越远 → 半影越宽（柔和）
- 光源越大 → 半影越宽

<PCSSPenumbraLab client:only="react" />

### PCSS 三步法

**Step 1 - Blocker Search（遮挡物搜索）：**

在光源方向的一个搜索区域内，找到所有比当前点更近的深度值，取平均。

```glsl
float findBlockerDistance(sampler2D shadowMap, vec2 uv, float zReceiver) {
    float searchRadius = LIGHT_SIZE * (zReceiver - NEAR_PLANE) / zReceiver;
    float blockerSum = 0.0;
    int blockerCount = 0;
    
    for(int i = 0; i < BLOCKER_SEARCH_SAMPLES; i++) {
        vec2 offset = poissonDisk[i] * searchRadius;
        float shadowMapDepth = texture(shadowMap, uv + offset).r;
        
        if(shadowMapDepth < zReceiver) {
            blockerSum += shadowMapDepth;
            blockerCount++;
        }
    }
    
    if(blockerCount == 0) return -1.0; // 无遮挡
    return blockerSum / float(blockerCount);
}
```

**Step 2 - Penumbra Size Estimation（半影宽度估算）：**

```glsl
float penumbraSize(float zReceiver, float zBlocker) {
    return (zReceiver - zBlocker) / zBlocker * LIGHT_SIZE;
}
```

**Step 3 - PCF with Variable Kernel（可变核 PCF）：**

```glsl
float PCSS(sampler2D shadowMap, vec4 coords) {
    vec2 uv = coords.xy;
    float zReceiver = coords.z;
    
    // Step 1: Blocker search
    float avgBlockerDepth = findBlockerDistance(shadowMap, uv, zReceiver);
    if(avgBlockerDepth == -1.0) return 0.0; // 完全无阴影
    
    // Step 2: Penumbra estimation
    float penumbraRadius = penumbraSize(zReceiver, avgBlockerDepth);
    
    // Step 3: Variable PCF
    return PCF_Filter(shadowMap, uv, zReceiver, penumbraRadius);
}
```

### PCSS vs PCF 对比

| 特性 | PCF | PCSS |
|------|-----|------|
| Kernel 大小 | 固定 | 随距离变化 |
| 物理正确性 | 无 | 近似 |
| 性能开销 | k² 次采样 | ~2× PCF |
| 适用场景 | 通用 | 中高端硬件 |

**PCSS 的问题：**
- Blocker search 区域难以确定
- 多个遮挡物在不同深度时，平均深度不准确
- 仍然是统计近似，不是真正的物理模拟

## 04 / VSM：用方差绕过多次采样

> 核心问题：能否预先模糊 shadow map，运行时只采样一次？

### VSM 的核心思想

Variance Shadow Maps (VSM) 用统计学技巧绕过 PCF 的多次采样：

**存储内容：不只存深度，还存深度的平方**
- 第一个通道：深度均值 E(z)
- 第二个通道：深度平方均值 E(z²)

**关键公式 - Chebyshev 不等式：**

$$
P(x > t) \leq \frac{\sigma^2}{\sigma^2 + (t - \mu)^2}
$$

其中方差：

$$
\sigma^2 = E(z^2) - E(z)^2
$$

### VSM 的实现

**Pass 1 - 生成 VSM：**
```glsl
// Fragment Shader (Light Pass)
void main() {
    float depth = gl_FragCoord.z;
    fragColor = vec2(depth, depth * depth);
}
```

**Pass 2 - 查询阴影：**
```glsl
float VSM(sampler2D vsmMap, vec2 uv, float fragDepth) {
    vec2 moments = texture(vsmMap, uv).rg;
    float mean = moments.x;
    float variance = moments.y - mean * mean;
    
    // 完全在前面，必然无阴影
    if(fragDepth <= mean) return 0.0;
    
    // Chebyshev 上界
    float d = fragDepth - mean;
    float pMax = variance / (variance + d * d);
    
    return 1.0 - pMax; // 转换为阴影值
}
```

**关键优势：**
- 可以预先对 VSM 做高斯模糊（因为期望和方差可以线性插值）
- 运行时只需一次纹理采样
- 支持硬件 mipmap 和各向异性过滤

### VSM 的致命问题：Light Bleeding

当多个深度层叠加时，方差估计会出错，导致**漏光现象**。

**场景示例：**
- 遮挡物深度 0.3
- 接收面深度 0.7
- VSM 区域包含两者，均值 0.5，方差较大
- Chebyshev 给出的概率偏大 → 本应全暗的区域出现漏光

**缓解方法：**
- 减小模糊半径
- 使用 EVSM（Exponential VSM）
- 配合传统 PCF 混合使用

## 05 / 实时阴影技术对比

| 技术 | 采样次数 | 物理准确性 | 主要问题 | 适用场景 |
|------|---------|-----------|---------|---------|
| **Hard Shadow** | 1 | 无 | 边缘生硬 | 风格化、极限性能 |
| **PCF** | k² (9-49) | 无 | 固定软化，非物理 | 通用实时渲染 |
| **PCSS** | ~2×PCF | 近似 | 性能开销大 | 中高端PC |
| **VSM** | 1 | 近似 | Light bleeding | 特定场景 |
| **RTX** | 可变 | 高 | 需要硬件支持 | 现代GPU |

## 06 / 核心要点总结

### 一句话总结

```text
实时阴影 = 性能预算内逼近物理真实的可见性查询
```

### 关键认知

1. **PCF 不是模糊深度**，而是平均比较结果
2. **PCSS 的核心**是blocker search + 可变kernel
3. **VSM 的优势**是预计算模糊 + 单次采样
4. **VSM 的缺陷**是多深度层的light bleeding
5. **所有技术**都是在质量、性能、内存间权衡
