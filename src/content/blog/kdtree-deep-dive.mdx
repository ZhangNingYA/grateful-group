## 什么是 KD-Tree？

**KD-Tree**（K-Dimensional Tree）是一种用于组织 K 维空间中点的二叉树数据结构。它通过递归地用轴对齐的超平面将空间一分为二，使得最近邻搜索、范围查询等操作从暴力的 O(n) 降低到平均 O(log n)。

KD-Tree 在计算机图形学、机器学习、机器人学等领域有广泛应用：
- **光线追踪**：加速光线与场景物体的求交
- **最近邻搜索**：点云配准、KNN 分类
- **碰撞检测**：游戏物理引擎
- **粒子模拟**：N-body 问题

## 核心概念：递归二分

KD-Tree 的构建遵循一个简单的递归策略：

1. **选择划分轴**：通常按 depth % K 轮转（2D 交替 X/Y，3D 交替 X/Y/Z）
2. **找中位数**：在当前轴上对点排序，取中位数作为划分点
3. **划分空间**：中位数左侧的点进入左子树，右侧进入右子树
4. **递归**：对左右子树重复上述过程

这保证了树的平衡性——每次划分都将点集均匀分成两半。

### 构建算法伪代码

```
function buildKDTree(points, depth):
    if points.length ≤ 1: return leaf(points)
    
    axis = depth % K
    sort points by axis
    median = points[mid]
    
    return node(
        axis, median,
        left:  buildKDTree(points[0..mid], depth+1),
        right: buildKDTree(points[mid..n], depth+1)
    )
```

**时间复杂度**：O(n log n)（每层排序 O(n)，共 O(log n) 层）

## 最近邻搜索 (Nearest Neighbor)

KD-Tree 最经典的应用是**最近邻搜索**。算法的关键在于：

1. **递归下降**：根据查询点在划分轴上的位置，先搜索"更可能"的子树
2. **回溯检查**：如果查询点到划分平面的距离小于当前最佳距离，还需要搜索另一侧
3. **剪枝**：如果距离大于当前最佳，直接跳过整个子树

下面的可视化展示了搜索的每一步——注意黄色球体（搜索半径）如何不断收缩：

<KDTreeNNSearch client:only="react" />

### 搜索算法伪代码

```
function nnSearch(node, query, best):
    if node is null: return best
    
    d = distance(node.point, query)
    if d < best.dist: best = (node.point, d)
    
    axis = node.axis
    diff = query[axis] - node.point[axis]
    
    // 先搜索更近的一侧
    first  = diff < 0 ? node.left : node.right
    second = diff < 0 ? node.right : node.left
    
    best = nnSearch(first, query, best)
    
    // 关键：是否需要搜索另一侧？
    if |diff| < best.dist:
        best = nnSearch(second, query, best)  // 不能剪枝
    // else: 剪枝！跳过整个子树
    
    return best
```

## 光线遍历

在光线追踪中，KD-Tree 用于加速光线与场景物体的求交测试。光线从根节点开始，只遍历与光线相交的子空间：

<KDTreeRayTraversal client:only="react" />

### 光线遍历的关键优化

1. **前后顺序**：先遍历光线先到达的子节点
2. **提前终止**：如果在前半部分已找到交点，且交点在后半部分之前，可以跳过后半部分
3. **Mailbox 技术**：避免对同一物体重复求交（物体可能跨越多个叶节点）

## SAH 划分策略

简单的中位数划分保证了树的平衡，但不一定是最优的。**Surface Area Heuristic (SAH)** 通过最小化期望的遍历成本来选择划分位置：

$$
\text{Cost} = C_{\text{trav}} + C_{\text{isect}} \times \frac{N_L \cdot SA_L + N_R \cdot SA_R}{SA_{\text{parent}}}
$$

其中 SA 是表面积，N 是物体数量。SAH 的直觉是：**让包含更多物体的子空间尽可能小**。

<KDTreeSAHBuilder client:only="react" />

> 💡 **观察**：对于非均匀分布的点云，SAH 会选择一个偏向密集区域的划分位置，而非简单的中位数。这使得密集区域有更紧凑的包围盒，减少不必要的求交测试。

## KD-Tree vs BVH

KD-Tree 和 BVH（Bounding Volume Hierarchy）是两种最常用的加速结构。它们的核心区别在于：

- **KD-Tree**：划分**空间**（用平面切割）
- **BVH**：划分**物体**（用包围盒包裹）

<KDTreeVsBVH client:only="react" />

### 如何选择？

| 场景 | 推荐 |
|------|------|
| 静态场景、离线渲染 | KD-Tree（更紧凑的划分） |
| 动态场景、实时渲染 | BVH（支持 refit） |
| GPU 光线追踪 | BVH（硬件加速） |
| 点云处理 | KD-Tree（天然适合点数据） |

## 复杂度分析

KD-Tree 的核心优势在于将搜索从 O(n) 降低到 O(log n)。当数据量增大时，这个差距是巨大的：

<KDTreeComplexityVisualizer client:only="react" />

| 操作 | 暴力搜索 | KD-Tree |
|------|----------|---------|
| 构建 | — | O(n log n) |
| 最近邻查询 | O(n) | O(log n) 平均 |
| 范围查询 | O(n) | O(√n + k) 平均 |
| 插入 | O(1) | O(log n) |
| 删除 | O(n) | O(log n) |

## 维度灾难

KD-Tree 有一个重要的局限性：**在高维空间中效率急剧下降**。这被称为"维度灾难"（Curse of Dimensionality）。

原因在于高维空间的反直觉特性：
- 超立方体的体积集中在角落
- 超球体的体积集中在表面
- 所有点之间的距离趋于相等
- 划分平面无法有效地将搜索空间缩小

<KDTreeDimensionCurse client:only="react" />

### 经验法则

> 当维度 d > log₂(n) 时，KD-Tree 不再比暴力搜索快。

对于高维数据，考虑使用：
- **近似最近邻 (ANN)**：如 LSH、HNSW
- **降维**：PCA、t-SNE 后再用 KD-Tree
- **随机化 KD-Tree**：多棵树投票

## 总结

| 概念 | 要点 |
|------|------|
| 核心思想 | 轴对齐超平面递归二分空间 |
| 构建 | 轮转轴 + 中位数划分，O(n log n) |
| 最近邻搜索 | 递归下降 + 回溯 + 剪枝，O(log n) |
| KNN | 最大堆维护 K 候选，搜索半径动态收缩 |
| 光线遍历 | 前后顺序 + 提前终止 + Mailbox |
| SAH | 最小化期望遍历成本，适合非均匀分布 |
| vs BVH | KD-Tree 划分空间，BVH 划分物体 |
| 维度灾难 | d > log₂(n) 时退化，需要 ANN 替代 |

KD-Tree 是理解空间数据结构的基石。掌握了它的原理，你就能更好地理解 BVH、八叉树、R-Tree 等更复杂的结构。
