## Start with the scene

This section is for Three.js notes that should stay close to practice. Each note should connect an idea to something visible: a scene, a camera move, a material test, a light setup, a geometry experiment, or a shader sketch.

The first goal is not to memorize every API. It is to build a clear mental model for how a browser turns data into a rendered frame.

## Learning path

- scene, camera, renderer, and the render loop
- geometry, attributes, buffers, and transforms
- materials, textures, color, and lighting
- controls, interaction, raycasting, and animation
- shaders, post-processing, and performance checks

## Note format

Each future note should answer a few concrete questions:

1. What does this concept control in the rendered result?
2. What is the smallest demo that makes it visible?
3. What can break when the scene becomes larger or more interactive?

For now, this is the entry point. More focused Three.js notes can live beside it as separate MDX files under `src/content/threeD`.
